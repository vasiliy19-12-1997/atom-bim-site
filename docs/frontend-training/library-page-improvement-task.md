# Практическая задача: прокачка на `LibraryPage`

> Формат: ты делаешь самостоятельно, я как наставник проверяю по критериям ниже.

## Почему именно эта страница

Берём **`LibraryPage`**, потому что сейчас это почти пустая заглушка, и на ней удобно отработать сразу несколько важных тем без риска «сломать» сложную логику.

Текущая реализация:
- компонент: `src/pages/LibraryPage/ui/LibraryPage/LibraryPage.tsx`
- стили: `src/pages/LibraryPage/ui/LibraryPage/LibraryPage.module.scss`

## Твоя миссия

Сделай из заглушки полезную страницу «Библиотека» с:
- понятной структурой контента;
- состояниями `loading / empty / error / success`;
- фильтрацией и поиском;
- аккуратной адаптивностью;
- понятной типизацией и чистой архитектурой.

---

## Что нужно реализовать (по шагам)

### Шаг 1. Каркас страницы

Собери структуру из 4 зон:
1. Заголовок + короткое описание страницы.
2. Панель фильтров (поиск + селект категории).
3. Список карточек материалов.
4. Блок состояния (если список пуст / ошибка / загрузка).

**Ограничение:** не тащи сложные библиотеки UI, достаточно текущих компонентов проекта и CSS-модуля.

### Шаг 2. Модель данных и типы

Определи тип материала, например:
- `id`
- `title`
- `description`
- `category`
- `level` (`junior | middle | senior`)
- `durationMinutes`

Создай минимальный мок-датасет (5–8 записей) в фича/модель слое, а не прямо в JSX.

### Шаг 3. Фильтры

Реализуй:
- поиск по `title` (case-insensitive);
- фильтр категории (`all` + 3 категории);
- сброс фильтров одной кнопкой.

Важно: логика фильтрации должна быть вынесена в отдельную функцию/селектор, а не размазана по JSX.

### Шаг 4. Состояния интерфейса

Добавь 4 UI-состояния:
- **Loading:** скелетоны или хотя бы аккуратный прелоадер.
- **Error:** сообщение + кнопка «Повторить».
- **Empty:** сообщение «ничего не найдено» + кнопка сброса фильтра.
- **Success:** сетка карточек.

### Шаг 5. Адаптив и UX

Минимум:
- mobile: 1 карточка в ряд;
- tablet: 2;
- desktop: 3;
- фильтры не ломают вёрстку на узких экранах.

Плюс UX:
- кнопки имеют `:hover/:focus-visible`;
- поля форм доступны с клавиатуры;
- у инпутов есть label/aria-label.

### Шаг 6. Локализация

Вынеси все строки в `i18n` (ru/en), никаких захардкоженных текстов в компоненте.

### Шаг 7. Тесты (минимум)

Напиши хотя бы:
1. Юнит-тест функции фильтрации.
2. Компонентный тест: при пустом результате показывается empty state.

## Критерии «сделано хорошо»

- Нет `any` в новой логике без причины.
- Нет «магических строк» категорий в трёх местах — используй enum/const map.
- JSX читается сверху вниз, без огромных вложенных тернарников.
- Стили локальны, без утечек в глобал.
- Страница выглядит аккуратно на ~360px и на desktop.
